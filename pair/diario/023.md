### 5. Job de instalação

`install / <sistema> / Python 3.13`, nos três sistemas, `shell: bash` em
todos (no Windows, o bash do Git). Passos: gera o wheel com
`python -m pip wheel . --no-deps -w dist`; cria o venv em `$RUNNER_TEMP`;
instala só o wheel, com `--no-index`; e, com `working-directory` num
diretório vazio de `$RUNNER_TEMP`, roda com o Python desse venv:

- `python -I -c "import dark ..."`, que falha se o módulo não vier de
  `site-packages` (prova que o checkout não está no caminho);
- `dark --help`;
- `dark auditar --todos --config $GITHUB_WORKSPACE/tests/fixtures/config
  --sem-git --saida report.md`, e confere no relatório a linha
  `Sessões: 5 · Pedidos: 7`;
- `python -I -m dark.evals --help`.

Cada passo falha pelo código de saída (bash com `-e`, padrão do Actions).
Sem modo editável, sem `src` no caminho. As ações são as mesmas do job de
testes, fixadas pelo mesmo hash. Nada do pacote precisou mudar para
funcionar instalado, então nenhum passo tem `continue-on-error`.

Escolha: `--todos` em vez de `<checkout>` como caminho, porque as
sessões sintéticas não pertencem a repositório nenhum
(`repositorios: 0` no leitor); com o caminho do checkout o relatório sai
com 0 sessões e o critério 3 não teria o que comparar.
