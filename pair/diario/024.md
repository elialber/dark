## Decisões tomadas aqui

1. **`--todos`** (padrão a confirmar). O lote pede `dark coletar
   [<repositório>]`, padrão o diretório atual, que coleta só as sessões
   daquele repositório (mesma seleção de `dark auditar`, E3 e E15). Para
   guardar o histórico inteiro antes que o Claude Code o apague, acrescentei
   `--todos`, como em `dark auditar`: todas as sessões, de qualquer
   repositório, inclusive as sem repositório (gravadas com repositório
   nulo). A conferência do critério 3 usa `--todos`, porque os arquivos
   sintéticos não têm repositório git. Recomendação: o agendamento semanal
   (E10) deveria rodar `--todos`.
2. **Local do banco** (padrão a confirmar). O lote: recusar se cair em
   repositório git sem estar ignorado. O goal 017 previa também
   `open_store(..., outside=[repositórios auditados])`, que recusa mesmo
   caminho ignorado. Com `--todos`, isso recusava o próprio
   `$PAIRLOOP_SCRATCH` (ignorado, dentro deste repositório, que também é
   coletado). Fiquei com: (a) dentro do repositório pedido explicitamente,
   recusa sempre; (b) dentro de qualquer repositório git sem estar
   ignorado, recusa; (c) caminho ignorado em outro repositório, aceito.
3. **Sessão sem mudança não é regravada.** Antes de gravar, a coleta lê o
   registro guardado e compara com o novo; igual, conta como "sem
   mudança". Diferente (sessão em andamento, commit revertido depois),
   regrava: a última coleta vence (decisão 7 do diário 017).
4. **Sem git, as ligações guardadas ficam.** Com `--sem-git`, a ligação sai
   só da transcrição: hash registrado vira `recorded` (revertido e
   substituído nulos), sem hash vira `unlinked`. Se a sessão já tem
   ligações no banco, ficam as do banco, que sabem mais; assim uma coleta
   `--sem-git` não desfaz o que uma coleta com git gravou.
5. **Bloqueio de hook.** O esquema guarda (desfecho, evento, contagem),
   sem a marca `blocked` do leitor. Um hook de parada que impediu a
   continuação (`stop` com `preventedContinuation`) é gravado com o
   desfecho `stop_blocked`; `block` já é bloqueio. Bloqueios no banco =
   `block` + `stop_blocked` (`collect.BLOCKING_OUTCOMES`). Evitei mexer no
   esquema por isso (padrão a confirmar; a alternativa é uma coluna
   `blocked` com migração para a versão 2).
6. **Repartição por sessão**: `indicators.breakdown([sessão])`, somando as
   partes por `PART_GROUP`; o não explicado é medido menos a soma das
   partes (o buraco "repartição por grupo por sessão" do diário 017).
7. **Uso por sessão**: `indicators.dead_weight([sessão])`, que devolve os
   conjuntos disponível e usado de uma sessão, sem depender das funções
   internas `_used_*`. Origem: `provenance.classify` com o inventário do
   repositório da sessão, pelo nome que o peso morto usa
   (`audit._provenance_of`, função interna da auditoria, reaproveitada; se
   a auditoria mudar, a coleta acompanha). Sessão sem repositório ou cujo
   repositório não existe mais: origem nula. Nome usado fora da lista
   anunciada: origem nula.
8. **Ligação de commits**: `commit_linking.link_commits` sobre as sessões
   selecionadas (sem as de comando local), uma vez por coleta. `hash` →
   `recorded`, `window`, `ambiguous` e `unlinked` como no diário 017; um
   comando com N commits vira N linhas. `called_at` é o horário da
   chamada, procurado na sessão e nos subagentes. Revertido e substituído
   só têm valor quando o git respondeu: sempre na janela; no registrado,
   quando `amend_by_git` não é nulo. Hash registrado fora do esquema (não
   hexadecimal) vira `unlinked`.
9. **Desfechos de hook por sessão**: `Counter` de (tipo, evento) sobre
   `Session.hooks`, evento `?` quando o registro não diz, como em
   `indicators.hooks`.
10. **Repositório**: identidade por `cli.git_identity` (passada pelo
    `cli`, para o `collect.py` não importar o `cli`), raízes separadas por
    vírgula. Caminho: o pedido, senão o da sessão mais recente que ainda
    existe. `last_seen`: o maior fim de sessão; sem sessão nova, fica o
    guardado; repositório novo sem sessão, o horário da coleta. Assim a
    segunda coleta não muda a linha.
11. **Retrato**: um por repositório com caminho existente, data local da
    coleta (dois no mesmo dia ficam com o segundo, decisão 8 do diário
    017). Itens: tipo, escopo, nome, caracteres, caracteres da descrição,
    itens e itens com motivo; nada do conteúdo.
12. **Nomes fora do esquema** (mais de 128 caracteres, caractere de
    controle; identificador de sessão ou chamada inválido) são descartados
    e contados (`nomes fora do esquema, descartados` no resumo), em vez de
    derrubar a coleta. Sessão sem horário ou com identificador inválido é
    "recusada" e contada.
13. **Registro da coleta**: `started_at` é o início; `finished_at`, início
    mais a duração medida; `tool_version` pela `importlib.metadata`
    (`0+unknown` quando o pacote não está instalado); `failures` soma as
    falhas de leitura das transcrições (as do repositório, quando há
    caminho) e as do inventário.
14. **Mensagens**: as do comando estão em português. Os erros do pacote
    `dark.store` (banco travado, corrompido, versão nova) continuam em
    inglês, como vieram do goal 017, e o comando os imprime como estão;
    traduzi-los pede uma tabela de rótulos de erro (fica para o goal que
    integrar a auditoria ao banco).

## Texto proposto para o README (lote seguinte)

> ### Coleta
>
> O Claude Code apaga as transcrições antigas (30 dias, por padrão). Para
> comparar uma semana com a anterior por mais tempo, rode a coleta de vez
> em quando, por exemplo uma vez por semana:
>
> ```
> dark coletar --todos
> ```
>
> Ela grava, num banco local fora dos seus repositórios (no macOS,
> `~/Library/Application Support/dark/aggregates.sqlite3`; no Linux,
> `~/.local/share/dark/`; no Windows, `%LOCALAPPDATA%\dark\`), os números
> de cada sessão: pedidos, tokens, intervenções, desfechos de hook, peças
> disponíveis e usadas, ligações de commits e um retrato do inventário.
> Nenhum texto de conversa é gravado. Coletar de novo não duplica nada, e
> as sessões que o Claude Code apagar continuam no banco.
>
> Sem `--todos`, coleta só o repositório do diretório atual (ou o
> caminho dado). `--banco` escolhe outro arquivo; o comando recusa um
> arquivo dentro de um repositório git que não o ignore. `--sem-git` pula
> a consulta ao histórico git (mais rápido; as ligações já gravadas ficam).
