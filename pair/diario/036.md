## Decisões

- **Indicador `adherence`.** Regra com motivo é o mínimo para medir
  aderência depois; o módulo não escreve regra que possa envelhecer, então
  `freshness` não se aplica. *Padrão a confirmar.*
- **Exige git, e a raiz.** O caminho precisa ter `.git`. Subpasta de
  repositório é recusada, com a raiz indicada, em vez de subir sozinha: um
  comando que escreve não deve agir num repositório que o usuário não
  nomeou (a auditoria, que só lê, continua subindo). *Padrão a confirmar.*
- **Sem linha no `.gitignore`.** O que a ferramenta grava localmente
  (banco de agregados) fica no diretório de dados do usuário e a coleta
  recusa caminho dentro de repositório; rascunhos de caso vão para onde
  `--gravar` indicar. Não há o que ignorar, então o módulo não toca no
  `.gitignore`. O manifesto `.dark-scaffold.json` fica versionável de
  propósito (diz o que a ferramenta criou). *Padrão a confirmar.*
- **Plano só com o que falta.** O item entra no plano se o destino não
  existe (`lexists`, então link quebrado e diretório contam como
  existentes) ou se o manifesto registra esse caminho para o módulo (assim
  o motor responde "já aplicado" na segunda vez). Guarda de `evals/cases`
  é a pasta inteira: com `x.toml` do usuário, nem `LEIAME.md` nem modelo
  entram.
- **Linha de estado.** Conta as peças de harness do projeto (inventário
  lido com configuração de usuário e política gerenciada inexistentes, para
  não ler o harness pessoal). Não repete o relatório.
- **Códigos de saída.** `remover` de módulo nunca aplicado: 0 (nada a
  fazer); módulo desconhecido (nem no manifesto nem nos conhecidos): 2;
  algo mantido por edição do usuário: 1. *Padrão a confirmar.*
- **Remover módulo desconhecido mas registrado no manifesto** reverte
  mesmo assim (o motor trabalha por nome).
