## Decisões tomadas

Todas em `docs/decisoes.md`. As principais: tolerância de 4 em 15 por
condição (a diferença por caso só é anotada); SemVer `0.x`; URL do
repositório como marcador, sem nome de conta; `dark coletar --todos`
para a coleta semanal; o banco é recusado dentro de repositório git que
não o ignore; bloqueio de hook de parada gravado como `stop_blocked`,
sem mudar o esquema.

## Decisões que esperam você

**D1. Como corrigir os defeitos do laço de par.** Nenhum agente edita
`tools/pairloop/`. Lista: git do orquestrador com configuração
neutralizada e `.git/config` e `.git/hooks/` no retrato; arquivo de
hooks regerado a cada sessão; bytecode; comando de testes conferido na
partida; caminhos do Git Bash; rascunho do revisor dentro das raízes do
hook (o revisor não consegue criar cópia limpa nenhuma); destino de
`git clone` não conferido; variáveis não expandidas pelo hook; executor
sem poder remover os worktrees que ele mesmo criou.

- (a) Você abre uma sessão fora do laço, entre rodadas, com um goal de
  endurecimento com essa lista.
- (b) Liberar `tools/pairloop/` para um executor numa rodada, com o
  revisor conferindo.
- (c) Aceitar os riscos e seguir.

Recomendação: **(a)**. O laço não deve editar o próprio limite. Nenhum
goal da fila espera por ela.

**Pedidos (não são decisões):** um token dedicado no ambiente
(`CLAUDE_CODE_OAUTH_TOKEN` ou `ANTHROPIC_API_KEY`) para a calibração,
que é o que falta para fechar a Fase 3; a etiqueta `v0.1.0`, se quiser
